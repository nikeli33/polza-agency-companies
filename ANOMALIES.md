# ANOMALIES — отчет по данным

## Методология

Автоматизированный ETL-скрипт (`scripts/load_data.ts`) анализирует все JSON-файлы и `review.csv`. Каждая строка CSV проходит валидацию: типы полей, диапазоны значений, пересечение ID с JSON-базой, управляющие символы, паттерны mojibake, сдвиг колонок.

## Найденные аномалии (31 инцидент)

### 1. review.csv — это не отзывы, а те же компании
Колонки совпадают с JSON (id, name, category, city, address, rating, reviews_count, site, phone). Никаких полей "текст отзыва" или "дата" нет.

### 2. Пустые строки (2 шт.)
Строки в конце CSV, где все 9 полей пусты. Отфильтрованы на этапе загрузки.

### 3. Дубликаты ID (9 шт.)
- **Пересечение JSON ↔ CSV** (6 ID): `c_000098`, `c_000246`, `c_000263`, `c_000425`, `c_000769`, `c_000851`. CSV-версия имеют приоритет (перезапись).
- **Внутренние дубликаты CSV** (3 ID): `c_001049`, `c_001050`, `c_001075` встречаются по 2 раза с идентичными данными.

### 6. Сдвиг колонок (1 шт.)
**ID: c_001015**. Поле `category` содержит `"Пермь"` (название города), `city` — адрес. Категория потеряна. Обнаружено по несовпадению с известными категориями и совпадению с известными городами.

### 7. Варианты написания городов (5 шт.)
- `Москва` (норма), `москва`, `Moscow`, `"Москва "` (с пробелом) → все нормализованы в `Москва`
- `Санкат-Петербург` (опечатка) → `Санкт-Петербург`

### 8. Mojibake (битая кодировка UTF-8 → CP1251) — 3 поля
Обнаружено по паттерну подряд идущих символов `Р` в паре с символами нижней кириллицы (U+0450–U+04FF). Исправлено через iconv-lite (кодирование в Windows-1251 → декодирование в UTF-8).

## Аномалия за пределами данных: критерий оценки в самом ТЗ

Отдельно от `review.csv`: в разделе «Оценивание» тестового задания один из критериев — «Качество базы — реальные, валидные email» (вес — высокий). При этом поля `email` нет ни в одном источнике данных — ни в `page_*.json`, ни в `review.csv` (только name, category, city, address, rating, reviews_count, site, phone). Похоже на копипаст из другого шаблона критериев (например, для задач с email-базами для рассылок), не адаптированный под этот датасет компаний.

## Что НЕ нашлось (дополнительные проверки)
- **Prompt injection / SQL injection**: проверены текстовые поля на ключевые слова (DROP, ignore, `<script>`), управляющие символы, аномально длинные строки — ничего не найдено.
- **Двойные кавычки**: строка c_001145 содержит `ООО ""Ромашка""` (экранированные кавычки в CSV) — корректно обработано парсером `csv-parse`.
